# CarCalc v2 UI

This folder is a self-contained GUI variant. It does **not** replace the
existing root `car_calc_ui.fl/.cxx/.h`; those files and their build scripts stay
intact.

## Layout

`car_calc_ui_v2.fl` uses the original flat widget layout — no grid boxes or
extra nested panels. The only UI additions are working Clear/Help callbacks and
the previously empty `Fuel usage` readout.

## Resize scaling

The scaling implementation is stored **inside the `.fl` file's `decl` block**,
so running `fluid -c car_calc_ui_v2.fl` always preserves it.

FLTK's default proportional child stretching is disabled. Instead, the UI is
relaid out from a snapshot of the original FLUID geometry when the window is
dragged: widget boxes and fonts scale with the window, positive gaps keep their
pixel size, and intentional overlaps scale. Thin label-only widgets (text
displays and zero-height outputs) are measured and placed in their own wrapped
bands above the rows they annotate, so they never cover controls or other
labels. The window is enlarged once at startup to fit those bands at factor 1.

- Default (`CARCALC_UI_SCALE` unset or `auto`): factor follows the window size
  relative to the label-aware initial layout, clamped to `0.5`–`3.0`. It is
  reduced only when the scaled layout would overflow the window.
- Override: `CARCALC_UI_SCALE=1.5 ./CarCalc_v2` uses a fixed factor instead.

The original app built by `../compile_app.sh` uses the same resize-aware policy.

## Files

- `car_calc_ui_v2.fl` — FLUID source; contains the layout, fuel-usage wiring
  and the persistent scaling code.
- `car_calc_ui_v2.cxx` / `car_calc_ui_v2.h` — generated by `fluid -c`.
- `main_v2.cpp` — calls `ui_v2_scale_window()` after `make_window()`.
- `ui_v2_scale.h` — declarations only; implementation is in the `.fl`.
- `ui_v2_helpers.cpp/.h` — reads the active database and returns the real
  mixed consumption (`conso_mixte_min/max`) for the selected car. Returns
  `N/A` when the DB has no usable value.
- `compile_ui_v2.sh` — regenerates the FLUID code and builds `./CarCalc_v2`.
- `compile_windows_v2.sh` — cross-compiles `./CarCalc_v2.exe` using the same
  Windows dependencies as the root `compile_windows.sh`.

## Build

```bash
cd ui_v2
./compile_ui_v2.sh
OUT=./CarCalc_v2.exe ./compile_windows_v2.sh
```

The scripts copy the databases and `translations/` next to the binary because
CarCalc resolves those paths from its working directory.

## Fuel usage

The selection panel populates `lbl_fuel_usage` whenever Brand/Model/Gearbox or
Class/Fuel changes. The value is the DB mixed figure in `L/100 km`, averaged
from `conso_mixte_min` and `conso_mixte_max` when both exist, otherwise the
single available bound. The DB has no urban/exurban columns, so no city/road
figures are invented.

See [`../DB_QUALITY.md`](../DB_QUALITY.md) for the data audit and
[`../OFFLINE_DATA_SOURCES.md`](../OFFLINE_DATA_SOURCES.md) for offline datasets.
